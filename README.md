# Сервис заявок nikita_zozulenko

Зозуленко Никита Алексеевич, БИСТ-24-2-ПО. Этап 1 курсовой работы, вариант 2.
Сервис принимает заявки, хранит переписку, ведёт статусы «новая → в работе → закрыта», считает время первого ответа сотрудника и нарушение норматива категории. Сводка показывает открытые заявки и долю нарушений SLA по категориям.

## Требования
Docker Desktop с Docker Compose. Проверено: Docker 29.8.2, Compose 5.5.1, macOS 26.6 / ARM64. В контейнерах: Python 3.12.12, PostgreSQL 16.10, Flask 3.1.2, psycopg 3.2.10, Gunicorn 23.0.0. Клиент: HTML/CSS/JavaScript без сборки.

## Установка и запуск
Из корня скопированного или клонированного репозитория:
```sh
cp .env.example .env
docker compose up -d --build
docker compose exec api python seed.py small
```
Открыть http://localhost:8080, войти demo / demo. Учётная запись — сотрудник, ID 1. Страница позволяет создавать заявки, отвечать, менять статусы, смотреть список и сводку. База и схема: nikita_zozulenko. Seed пересоздаёт только данные этого учебного проекта; не использовать с чужой базой.

## Проверки
```sh
docker compose exec api python -m pytest -q
```
Тесты используют транзакции с откатом, данные для них готовятся seed. Есть бизнес-тесты SLA и переходов, а также проверки всех операций API, авторизации, ошибок и жизненного цикла заявки. Формирование индексов ограничено первичными ключами; кеширование отключено заголовком no-store и параметром fetch.

## Наполнение и замеры
```sh
docker compose exec api python seed.py small
docker compose exec api python benchmark.py small
docker compose exec api python seed.py work
docker compose exec api python benchmark.py work
```
Результаты сохраняются в results/small.json и results/work.json с сырыми 30 повторениями, p50, p95, максимумом, временами SQL и числом запросов. Перед каждой серией 5 прогревочных обращений. HTTP измеряется requests.Session внутри контейнера api: нет времени браузерного рендеринга и переноса порта Docker на хост. Подготовка заявок для PATCH и вход перед logout в замер не входят. Запись добавляет 71 заявку и 35 комментариев на каждом объёме (с учётом прогрева и подготовки). Все чтения выполняются раньше измерений записи. p95 — элемент ceil(0.95*N) отсортированного массива. Разложение использует средние парных повторов, а не разность независимо посчитанных медиан.

Время SQL — сумма отметок perf_counter вокруг execute и fetchall (включая обмен с PostgreSQL и преобразование строк); это время обращения к БД, а не чистое CPU-время PostgreSQL. Остаток HTTP минус SQL включает подключение, код, сериализацию, commit и транспорт. Число запросов считает явные операции SELECT/INSERT/UPDATE, не служебные BEGIN/COMMIT. Метрики доступны в X-DB-Ms, X-Query-Count, X-App-Total-Ms.

Повторное наполнение даёт одинаковые строки и контрольные суммы всех четырёх таблиц; seed печатает числа и hashes. Для воспроизведения сводки спустя время учесть: SLA без ответа считается относительно текущего времени, неизменные исторические строки остаются теми же.

## Программный интерфейс
Все API кроме login требуют cookie-сессии. JSON, временные поля сериализуются Flask в RFC 1123 GMT. Для ошибок ответ {"error":"код"}. Таблица полей — [CONTRACT.md](CONTRACT.md).

## Этапы дальнейшей работы
Не добавлены кеш, очереди, фоновые обработчики и индексы для поиска. Сводка агрегирует комментарии в SQL, затем считает итог по всем заявкам в Python. Это исходный вариант для дальнейшего измерения и оптимизации.
